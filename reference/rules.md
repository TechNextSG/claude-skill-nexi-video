# Rulebook (strict)

Every rule here is a MUST. A video that breaks one is not finished, however close the deadline.

**How the rules are enforced.** The **Check** after each rule says how it is caught:
- `lint:X` — `lint.py` runs inside `build_film.py`. An error means the film does not build.
- `audit:rule` — a `layout_audit.py` finding. The release gate fails on any HIGH finding, any medium finding parked for 1.5 s or more, and any resting group off-centre for 3 s or more.
- `gate:X` — `gate.py`. `render.py mp4` refuses to render and `deliver.py copy` refuses to copy until it passes.
- `look` — a manual check on the strip, the 12-frame sheet or the full-resolution CTA frame. No checker can see it, so you must.

**The training loop.** When a defect reaches the user:
1. Add the rule that would have caught it.
2. Extend `lint.py`, `layout_audit.py` or `gate.py` so it is caught automatically next time.
3. Log both in `lessons.md`.

A rule that was broken twice MUST become automated.

**No bypass.**
- Never loosen a threshold or a checker to make a film pass. Change a checker only to fix a proven false positive, and log the evidence in `lessons.md`.
- An exception is a waiver in `qa/waivers/<film>.json`, with a reason. Only intended effects qualify: chapter bands sliding in, a deliberately messy pile, a slider wipe. "No time" never qualifies.
- Every waiver used is told to the user in the delivery message.
- Truth and brand rules cannot be waived.

## F · Frame and composition (1920×1080 screen px)
| ID | Rule | Check |
|---|---|---|
| F1 | **Safe areas.** Nothing important under the HUD (x < 260, y < 140). Nothing the viewer must see behind the caption band: 1180 px wide, bottom-centred, its top at about y 880 for one line, 835 for two, 720 for three. | `audit:covered`, `audit:nexi-text` |

| F6 | **No leftovers from a previous scene** peek in at the edges. | look |
| F7 | **Vertical balance.** The content block sits between the HUD (y ≈ 140) and the caption top. Lower a top-heavy scene. | look |
| F8 | **60 px or more** between Nexi's silhouette and the nearest card. | `audit:nexi-text` + look |
| F9 | **A station's whole set is on screen when the camera lands.** Revealing cards one by one leaves the group left-heavy for 3 s or more. Each line highlights its own card (a glow, or a scroll unrolling), it does not add it. | `audit:offcentre` |
| F10 | **Frames on landing, content during the line (F9 + M12).** The screens, panels and cards stand when the camera lands; what is ON them builds while Nexi explains it. A scene that opens before any label exists (a city waking up) carries a narration box ("MEANWHILE, IN THE CITY") that anchors the composition until the scene's own labels arrive. | `audit:offcentre` + look |

**Framing math (do it for every scene):**
- `worldX = camX + (screenX − 960) / zoom` and `worldY = camY + (screenY − 540) / zoom`.
- Nexi's silhouette around `N.botPx()` (world px, depth 1): x −160..+160 (±200 with arms); y −230..+210 (top −310 with a tall hat or a reaction lift).
- The group: take the world extents of Nexi and every card, set the camera x to the group's centre, and set the zoom so the group spans about 1500 px or less.
- Typical layout: Nexi at screen x 340–470, cards from 600–650 to 1650–1700.

## K · Code safety (engine)
| ID | Rule |
|---|---|
| K1 | Film globals never reuse engine names (the `build_film.py` guard). |
| K2 | Never tween a whole array, and initialise every field you tween (a NaN tween silently draws nothing). |
| K3 | Every `save()` has its `restore()`. Delete dead drawing code instead of half-deleting it. |
| K4 | `L.tween` cannot be cancelled. Compute anything that must stop on cue from a start and a pause time. |
| K5 | `zap()` only targets Odoo UI hotspots. A tap on a world prop is a ring plus a tap clip. |
| K6 | A new costume goes in `build_core.py buildWear()`, is built up front, and its colours go through `convertSRGBToLinear`. |
| K7 | JS and patch scripts are written with the Write tool, not Bash heredocs (heredocs break JS, and the Bash tool halves backslashes). Patches assert-and-replace. |
| K13 | **`line.w(word)` is a case-insensitive substring search:** cue on a unique phrase (`w('Alt + H')`, not `w('H')`, which matched the h in "changes"). |
| K12 | **Check the port pair before every Chrome job.** Another session's Chrome on your CDP port makes `AUDIT.end()` return a dict and render.py dies with "the JSON object must be str ... not dict". Switch to a private fallback pair (3996-3999 / 9396-9399) with a fresh profile; never kill the other process. (QT15-24 2026-10-04) |
| K16 | **Resume a stopped or rate-limited agent with SendMessage** (its context is intact) and give it the exact state: which films have `qa/gate/<film>.json` (stage, ok), which MP4 is newer than its build, which steps (music_tune, mp4strip) still need running. A fresh agent would re-read every kit. (QT25-34 2026-10-05) | report |
| K17 | **Check the output files' times after every `thumbs.py` run:** with another session's Chrome on the CDP port the run printed nothing and left the old PNG/JPGs in place. Thumbnail renders use a private pair too (3983/9383 was free). (QT25-34 2026-10-05) | `ls -la out/thumbs` |
| K11 | **Shared film code lives in `web/films/inc/<name>.js`** and is pasted in by `build_film.py` from a line `  /*@include <name>*/`; never in the engine (an engine edit changes EVERY film's fingerprint). Changing an include changes the bundle of every film that includes it, so freeze an include before parallel agents start, and rebuild + re-audit its films after any change. Films must not reuse engine names either (CH, ENV: QT05's first build was refused for `CH` and `ENV`). |
| K10 | **Anything under `web/assets` is in EVERY film's fingerprint** (name + size). Adding a thumbframe, logo or channel art invalidates every audit and render stamp: add assets only after the films in flight are delivered, or work in a sandbox copy. |
| K8 | Never call `at()` inside an `at()`/`later()`/mover callback: the event list is sorted once, so a late `at()` runs at the very end. Inside callbacks use `later(d, fn)`. Check: `lint:K8` (p37). |
| K9 | A timed build's start time defaults to `1e9` (not yet), never `-9`: `t - (-9)` is already past every step, so the screen shows finished before its line. Every formula on `t - T0` guards negative time (`Math.max(0, t - T0)`, `if (a > 0)`), including `%` cycles, which go negative. Check: look at the strip frame on the line start. |
